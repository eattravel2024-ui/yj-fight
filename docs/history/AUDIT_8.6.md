# 《阿志向錢衝》8.6 全面技術、玩法與美術健檢

檢查依據：8.5 原始更新包中的 `server.js`、`public/game.js`、`public/team.js`、`public/core.js`、`public/team-core.js`、`public/rollback.js`、`public/index.html`、`public/team.html`、現有測試與部署腳本。8.6 以此原始碼修改，並且額外通過 80 項自動測試。以下是**程式碼審閱**與部分**瀏覽器版面檢查**，不是 VPS 的實機延遲或攻擊測試。

## 8.6 已實作

- 1v1 玩家暱稱：自訂 2–16 字；會出現在戰鬥血條與玩家清單；可以在房間內更新。
- 2v2 玩家暱稱：進房前自訂、進房後可更新；顯示於房間席位、隊伍血量 HUD、戰鬥角色頭頂。
- 觀戰者暱稱：建立觀戰連線時傳送，由伺服器同步可讀名單；觀眾無法控制戰鬥。
- 自訂房名：1v1／2v2 第一位選手（房主）建立或更改 2–24 字房名；其他選手／觀眾沒有改房名權限；房主離開會轉移權限。
- 暱稱及房名伺服器端驗證：允許中英文字母、數字、空格、底線、句點及連字號；拒絕控制與 HTML 特殊符號、常見官方／管理員名稱；同房暱稱不得重複；限制頻繁改名；舊版連線客戶端提供預設安全名稱。
- 暱稱存在當前瀏覽器的 `localStorage`，單人進度與 1v1 / 2v2 可共用一個本地顯示名稱。名稱不進入 Rollback 確定性模擬狀態，不改動 60Hz 戰鬥判定。
- 針對無效進房暱稱拒絕在建立房間之前執行，避免創建空房間耗盡房間限額。

## P0 — 對外營運前應優先處理

| 問題 | 程式依據 / 風險 | 建議 |
|---|---|---|
| 玩家身分不能驗證 | `server.js` 以房號 + 連線綁定身分，暱稱可自填；斷線後別人可能用相同暱稱。新命名功能不等於登入系統。 | 訪客帳號 ID、短期簽署房間憑證、重連 token，必要時才加入正式帳號登入。 |
| 房間權限不足 | `/ws` 以房號允許入場與觀戰，知道房號的人就能嘗試加入。 | 房主產生獨立玩家邀請／觀戰 token、私密房、封鎖觀眾；房號不要充當授權憑證。 |
| 明文 HTTP / WS | 目前 `http://YOUR_VPS_IP:18071/` 是未加密的 HTTP，對應 `ws://`。 | 使用網域 + HTTPS/WSS，保留 127.0.0.1:31071 內部 Node 端口，透過既有 Nginx 443 反向代理。 |
| 玩家斷線破壞賽局 | `server.js` 的 `leave()` 將 session 歸零，所有人得等待下一場。 | 斷線保席 30–60 秒、重連 token、無輸入時防守／暫停規則、重連後權威補同步。 |
| 真正網路實測不足 | 現有 server protocol 測試多為 FakeSocket/mock，尚無四台設備跨網路實戰佐證。 | 在 VPS 測試丟包／抖動／100–250 ms RTT、CPU/記憶體、回滾數、整場完成率。 |

## P2 — 美術、社群與營運品質

- **角色美術**：將高解析 Cut-in 素材整合到角色選角／勝利演出；若要真正逐格高解析戰鬥，須重新規格化 Sprite Sheet 的人物錨點、碰撞框和每幀方向，不能直接裁切不規則宣傳拼貼圖。
- **戰場攝影機**：雙人或四人遠離時平滑縮放，靠近牆角時保持角色可見；特效遮罩應避免擋住 HP 與地面落點。
- **打擊與音效**：每位角色提供獨立攻擊音色、受擊聲、防禦聲和勝利語音；音量分軌、靜音、動態範圍限制；確保音樂／音效權利可用。
- **觀戰／社群**：好友常用房間、表情反應、賽後精彩片段、觀眾投票 MVP；如增加聊天室，要規劃防騷擾、頻率限制和舉報機制。
- **無障礙與控制**：可自行改鍵（Mac）、手把 Gamepad API、對色盲友善的隊伍標記、低動態偏好、字幕和特效／抖動畫面強度。
- **進度保存**：目前單人進度只在 `localStorage`，換瀏覽器或清除快取會遺失。後續可加入帳號存檔、匯出／匯入、伺服器端戰績保存。
- **性能**：限制角色貼圖同時載入／減少一口氣載入多張大型素材、根據 DPR 調整畫質；服務端增加房間 CPU、事件迴圈延遲、封包大小與記憶體監控。
- **反作弊與安全**：檢查對局輸入序列、限制名稱與房間修改請求、對拒絕服務做 IP 級速率限制；伺服器權威判定不應以客戶端 HP 作最終結果。
- **部署與可維護性**：加入 CI（Node LTS、多瀏覽器）、自動化 WebSocket 端到端測試、版本化資料庫／設定檔備份、健康檢查含依賴狀態、逐步 rollout/快速回滾。
