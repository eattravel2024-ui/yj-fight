# 自訂對戰與首頁修正 — 8.11.3

日期：2026-10-16（UTC+8）。基準：`7c2473d`／8.11.2。沿用 `feat/arcade-phase1`，提供 Git 固定檢查點，不連線或部署正式 VPS。

## 本次完成

- 首頁「有請公子，上擂台」移至右側模式標題下方，改為小型文字，離開角色立繪區。金沙賭神與阿志不再被黃色標語遮住；桌面、直向／橫向手機均檢查。
- 主選單整合成五項：街機闖關、自由練習、自訂對戰、遊戲設定、操作與招式。原 1v1、2v2、觀戰功能均移入自訂對戰，沒有刪除玩法。
- `custom-room.js/css` 是共用介面適配器，左右分為自己的角色／暱稱及房間操作／選手席位；建立新房與加入既有房號分開，連線後突出房號、實際名單、角色及 Ready。加入後的改房名與連線資訊收在進階展開區；邀請、觀戰連結、離開、再戰均保留。
- 角色切換使用既有完整選角頁，確認後等待伺服器名單回覆；Ready、全員就位及房主開賽仍由伺服器管理。觀戰者不能選角、Ready 或占選手席。房內禁止直接切換規則，需先離開，不會偷偷中斷現有房間。
- 正式 `AzhiGame.connectRoom(intent)` 連到原生客戶端流程；`selectionContext().needed` 讀取伺服器席位數。原控制 ID／處理器保留在隱藏相容區，舊網路回歸案例明確以程式操作舊處理器；新增介面案例使用真正按鈕操作，不拿隱藏按鈕當新 UI 驗收。
- `server.js` 僅增加可選 `intent: create | join` 的驗證：輸錯房號的 join 不建立房間；create 不覆蓋既有房號；無效 intent 拒絕；失敗轉房不離開原房。未帶 intent 的舊客戶端保持原協議，沒有改戰鬥／Rollback／房主權限。
- 1v1 保留加入失敗的明確錯誤，不再被一般斷線訊息覆蓋。背景、碰撞、招式、傷害、動畫、HUD、OST、存檔均沿用原版。

## 匹配與排位：建議後續順序，尚未實作

1. **快速配對（不計分）**：先做 1v1 佇列、取消配對、等待狀態與斷線清理；伺服器配到兩人後建立普通 Ready 房間，沿用目前對戰與開賽流程。人數少時允許取消回自訂，不假裝已找到真人。
2. **穩定玩家身份與資料保存**：排位不能只認可改名的暱稱或瀏覽器自行上報的積分。建立伺服器驗證的帳號／玩家 ID，保存比賽紀錄與等級；資料放在獨立 DATA_DIR（例如 `/var/lib/azhi71`），避免換版部署覆寫。這些是後續設計，尚未建立該路徑或資料庫。
3. **排位 1v1**：從伺服器確認的結果結算 Elo/MMR，每個 match ID 只結算一次；加入定位賽／段位顯示前，先完成重連寬限、斷線勝負與取消規則。不能把自訂戰績或前端假分數當正式排位。

建議下一個可部署版本先完成快速配對，再做排位。自訂對戰目前明確標示「不計排名」，沒有假配對按鈕或已上線排位的宣稱。
