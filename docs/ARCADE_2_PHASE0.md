## 1. 結論

目前是具備實際戰鬥與多人功能的原生 JavaScript／Canvas 遊戲，可以在現有架構上升級，無需改用框架或重寫格鬥引擎。最需要補的是「選單選擇 → 合法準備 → 真正開戰 → 確認結果」的統一流程與資料契約。

現有五章街機、四角色、三個實際場景、真實血量／技能資料、Ready／房主開賽、Rollback、1v1／2v2／觀戰、觸控及舊冒險模式均應保留。尚無獨立任務列表、玩家選圖、可配置練習對手、手把、公開房間列表與真正斷線恢復。

既有測試通過不代表沒有缺陷。本次另重現舊存檔可造成啟動失敗、無效角色存檔造成選角顯示錯誤，以及練習換回合後能量重置問題。正式開始 UI 重構前，應先把這些已知路徑列入回歸。

## 6. 目前實際操作流程

- **街機**：大廳選街機與角色 → 直接啟動目前存檔章節 → 出場／戰鬥 → 勝敗 overlay → 下一關／重試。沒有獨立任務／選圖步驟。
- **練習**：大廳選角色 → 維尼木樁＋harbor → 訓練／計時與回合 → 返回選單；無對手／地圖／進階訓練設定。
- **1v1**：房間頁建立／加入 → 改角色 → 全員 Ready → 房主開始 → 伺服器選圖、同步戰鬥 → 確認完賽 → 再戰準備。
- **2v2**：團隊入口 → 建立／加入四人房 → 四人選角／Ready → 房主開始 → 固定隊伍戰鬥 → 全員準備再戰。
- **觀戰**：觀戰頁輸入房號／連結 → 等待或讀取進行中比賽 → 唯讀快照 → 等待下一場；沒有房間列表。
- **暫停／返回**：Escape 開一般大廳。本機停止步進；線上不停伺服器，清除按鍵並送中性輸入。新版不得改壞此差異。

### 網路及安全界線

已有：訊息／角色／名稱驗證、模式／席位／觀戰動作限制、4KiB payload、每 socket 頻率限制、背壓、heartbeat、CSP、靜態路徑邊界與有 Origin 時的同 host 檢查。既有惡意字串／畸形 join 測試通過，歷史 8.6 的角色崩潰問題不能再當成目前未修缺陷。

仍缺：私密／密碼／玩家與觀眾邀請授權、per-IP／身分配額、重連憑證、持久恢復。房號不是身分，缺 Origin 的非瀏覽器連線也可進入；不能用 CORS／前端隱藏按鈕取代權限。

200 房／500 連線等是程式上限，不是已驗證容量。回滾、複製、hash、JSON 與各房間共用一個 event loop，過載時排程會捨棄過多累積時間；`60Hz` 常數不等於壓力下維持真實 60Hz。既有 `tools/benchmark-rollback.cjs` 只量合成引擎延遲，不代表真實 TCP、多人負載或正式 VPS 效能。本次未連線檢查正式 TLS／WSS／Nginx。

## 8. 建議修改架構

維持原生 JS、Canvas、既有兩個入口與兩核心。以下是**後續提案，尚未新增模組**：

1. **Flow Coordinator**：管理畫面及選擇草稿，驗證合法轉換；資料包含 mode、missionId、player／opponentCharacterId、stageId、difficulty、preparationStatus、result reference。roomId／roster／Ready 由連線 adapter 提供。HP、倒數、技能、結果權威仍來自引擎／伺服器。
2. **正式 Game Adapters**：包裝既有本機開始、返回、連線、選角、Ready、重試、下一關與狀態讀取，逐步取代 shell 對 Debug API 的正式依賴。保留舊 ID／事件直到替代流程驗證完成。
3. **唯一 Mission／Stage Registries**：現有五章與三場景抽出可共用資料。不要在 shell 再複製章節陣列；純資料模組可於 Node／瀏覽器共用。戰鬥幾何第一版不變。
4. **Preparation／Asset Loader**：集中已選角色與場景的資源狀態，錯誤可重試，使用一次性準備 token／防連點；切換或取消使舊非同步結果失效。只保留需要的快取。
5. **共享 Menu Input／UI Audio**：只在對應 context 啟用，輸出現有 normalized keys／pulses；處理文字輸入、死區、按住重複節奏、手把斷線與 listener 清理。
6. **漫畫 UI Tokens／Components**：以 #09090F／#38101F 為底、#FF3558 主操作、#FFD43B 確認、#00D9F5 對手／次要訊息；少量斜切背景、硬邊陰影、低對比網點。內容不 skew、不讓所有區塊常駐閃爍，沿用 reduced-motion 與 native dialog 無障礙。

### 線上選圖契約

伺服器持有房間 stageSelection，保留 random 為相容預設，白名單為 random／night／garage／harbor。房主只能在非對戰中以 revision 修改；有效變更重置全員 Ready、遞增 revision 並廣播。一般玩家／觀眾唯讀，無效或過期請求不改設定。開賽時伺服器只解析一次隨機地圖，傳入既有 create，所有玩家與後加入觀眾讀同一 game.stage。再戰保留設定，Ready 流程仍由伺服器掌握。

任務固定圖只能確認；自由選圖任務受 allowedStageIds 限制。第一版五章保留現有固定地圖，不強加額外規則。若加入房間列表，必須先有真正受限的 server 查詢契約；在此之前保留清楚的「輸入房號觀戰」，不能造假房間人口。
